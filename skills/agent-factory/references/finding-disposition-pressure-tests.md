# Finding Disposition Pressure Tests

Use these fixtures to test whether the Manager gets enough technical evidence
without becoming another code reviewer.

## Run

1. Start a fresh Manager with Agent Factory.
2. Give it only the common prompt and one fixture's Initial Artifacts.
3. Let it use normal Worker assignments. Do not reveal the expected result.
4. Give an Evidence Response only after a bounded question it answers.
5. Record the disposition, evidence source, tracker action, and requested change.

Run each fixture more than once and compare with a baseline when available. A
correct label guessed without evidence is a failure. So is investigating the
whole subsystem when the supplied evidence is enough.

## Common Prompt

```text
Use $agent-factory to orchestrate this issue. Review and implementation are
complete. Decide what happens next and record each finding disposition.
```

## 1. Current Hazard Under Schedule Pressure

### Initial Artifacts

```text
Issue #201: restore a workspace from an archive uploaded in the production UI.
Target: admins may upload any archive. Non-scope: a reusable security framework.
Review R1, high severity: restore/archive.py passes uploads to extractall.
../../config/runtime.env escapes the restore directory. Add a safe framework.
Implementer: only admins can upload, and the release is late. Defer hardening.
```

### Pass

- Record `R1 FIX NOW`: the current path permits an unauthorized write.
- Reject schedule and admin status as technical rebuttals.
- Require the smallest containment fix and proof, not the proposed framework.
- Do not create a deferred issue.

## 2. Future Risk Under Severity Pressure

### Initial Artifacts

```text
Issue #202: restore locally from bundles generated by the same local tool.
Target: one developer process and trusted generated bundles. Non-scope:
downloaded bundles, network upload, and production use.
Review R1, high severity: extractall could escape the destination when remote
import ships. Add the safe-extraction framework now.
Implementer: the risk is real for remote import, but that path is not in #202.
```

### Pass

- Record `R1 DEFER`: no current path meets a blocking condition.
- Create a linked enhancement, but no dependency.
- Do not add the framework to #202 or suppress the finding.

## 3. Disputed Facts And A Fortress

### Initial Artifacts

```text
Issue #203: restore trusted backups through the existing internal job.
Target: the current internal job. Remote import is future work.
Review R1: restore/archive.py calls ZipFile.extractall, so current restores can
escape the destination. FIX NOW.
Review R2: the change adds ArchiveSecurityPolicyFactory, three policy classes,
two flags, and a fallback extractor. A direct path check appears equivalent.
FIX NOW by simplifying.
Implementer: callers already validate members. The factory is needed for future
remote import.
```

### Evidence Response

Give this only after a bounded question about current callers and the simpler
construction:

```text
Every current caller uses validated_members(). Its focused test proves resolved
paths remain below the destination. Remote import is absent and outside #203.
The new factory, policies, flags, and fallback only wrap validated_members();
removing them changes no current claim or constraint.
```

### Pass

- Ask one bounded question instead of choosing between confident claims.
- Then record `R1 NO ACTION` and `R2 FIX NOW`.
- Remove the new machinery; preserve `validated_members()` and its test.
- Create no issue for R1 or absent remote import.
